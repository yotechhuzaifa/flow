# flow

Cross-platform desktop flow builder (Windows · macOS · Linux). Wails v3 shell, React Flow canvas,
SQLite storage. Clone the flow part first, then add features on top — `docs/SCALE.md`.

Repo source is **~420 KB / 100 files**. Everything heavy (Go SDK, module cache, `node_modules`,
`dist`) is ignored and never committed.

## Start

```bash
bash scripts/toolchain.sh   # only if `go` is missing; installs outside the repo
bash scripts/setup.sh       # checks tools, prints exactly what to install
npm install                 # root: @playwright/test for the parity suite
npm --prefix frontend ci    # frontend deps
make webui                  # build + sync internal/webui/dist
make dev                    # native window + hot reload (needs wails3 + build/ assets)
opencode  →  /start         # let the agent run the parity queue
./scripts/loop.sh           # same, unattended and restart-safe
```

Desktop packaging (`make dev`, `make build`, `make package`, `make cross-*`) needs the Wails v3 CLI
and the `build/` task files. They are not vendored yet; until they are, use the headless path:
`make test`, `make build-server`, and `make e2e` all work with Go + Node alone.

## Layout

```
cmd/app                  desktop entry (Wails)
cmd/server               headless entry, -tags server
internal/domain/flow     Flow · Node · Edge · TopoSort · Validate    ← stdlib only
internal/domain/run      Run · statuses · failure propagation
internal/nodes/          one file per node type + registry
internal/exec/           run orchestration + events
internal/sqlite/         persistence + migrations (pure Go, no cgo)
internal/wails/          desktop transport
internal/transport/httpapi  server transport (HTTP + SSE)
internal/webui/          go:embed of the built frontend (synced by `make webui`)
internal/app/            composition root — the only place that wires layers
internal/platform/       data dir, GOOS
internal/events/         event names, allow-listed
frontend/src/features/   canvas · nodes · runs
frontend/src/shared/     types (mirrors CONTRACT) · api client · hooks
build/                   Wails v3 build assets — not vendored yet (see docs/platform-setup.md)
scripts/                 toolchain · setup · check · dod · loop · sync-webui
docs/                    ARCHITECTURE · CONTRACT · SCALE · platform-setup
parity.csv               the work queue (12 MUST rows)
```

## Commands

| | |
|---|---|
| `make dev` | hot-reload desktop app |
| `make test` | go tests + typecheck, no webview needed |
| `make check` | the fast gate the loop uses (~5s once deps are installed) |
| `make build` / `make package` | binary / native installer for the host OS (needs Wails assets) |
| `make build-server` | headless HTTP build for CI and parity tests |
| `make e2e` | parity suite |
| `make cross-win` `cross-linux` `cross-mac` | cross-compile (Windows needs no cgo) |

## Rules the codebase enforces

- `internal/domain` imports nothing but the standard library. It survives every rewrite.
- Only `internal/app` imports across layers. Other packages talk inward.
- A new node type touches four files and never `internal/exec`.
- `bash scripts/check.sh` stays under 60 seconds.
- `dod.sh` fails if `GOAL.md`, `docs/CONTRACT.md` or the gate scripts change, so an agent cannot
  make the loop pass by editing the goal.

## Keep the workspace small

The session snapshot budget is 128 MB / 10k files. Never leave these in a synced folder:

| Never commit | Why | Where it belongs |
|---|---|---|
| `node_modules/` | ~68 MB, 3.3k files | local, after `npm ci` |
| Go SDK | ~1.4 GB, 38k files | `~/.local/share/gotoolchain` (`scripts/toolchain.sh`) |
| `GOMODCACHE` / `GOCACHE` | hundreds of MB | `~/.local/share/gomodcache`, `~/.local/share/gocache` |
| `frontend/dist/` | build output | regenerated by `make build` |
| `*.db` | runtime data | `internal/platform.DataDir` |

`scripts/toolchain.sh` sets `GOMODCACHE` and `GOCACHE` outside the repo so `go test` never writes
into it.
